# Validation and representativeness boundaries

## Research question

> Does validation require an explicit documentary responsibility for determining whether represented knowledge remains applicable, representative, or sufficiently supported?

## Evidence from Context review

Context currently contains two related but distinct question families:

~~~text
Applicability
    -> Where is this context representative?
    -> Where does it stop being representative?

Potential obsolescence
    -> What conditions could change?
    -> What signals would indicate that it is no longer representative?
~~~

These should not be merged merely because they both concern representativeness.

The current distinction is:

~~~text
applicability boundary
    = where the representation is already known to apply or not apply

future loss of representativeness
    = what changes could make a currently valid representation cease to apply
~~~

This may be relevant to a future Validation Document because both families concern the conditions under which represented knowledge can still be treated as valid or representative.

However, current evidence does not establish that Validation owns them.

## Relationship with Drift

A further distinction must be preserved:

~~~text
validity / applicability condition
    = what would make knowledge cease to hold

Drift
    = observed unreconciled divergence between
      represented knowledge and current reality
~~~

Validation may eventually evaluate whether knowledge satisfies its validity conditions, while Drift may preserve the divergence once it is observed.

This relationship remains open.

## Open questions

- Is Validation a distinct Document responsibility?
- Does Validation evaluate represented knowledge against explicit validity conditions?
- Is representativeness a Validation concern or intrinsic to each source Document?
- Should source Documents retain applicability conditions even if Validation is formalized?
- How does Validation differ from Verification?
- How does Validation differ from Drift?
- Can Validation determine that a Context remains valid without duplicating the Context itself?
- Does Validation require evidence, criteria, or both?
